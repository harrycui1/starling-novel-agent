---
title: 网文续写流程规划
---

**一句话结论：质量问题不在文笔，而在动笔前的决策。** 流程的重心放在三处：从哪里切、守住什么类型、后 2 万字靠什么冲突撑起来。写作线保持全文注入、不阻断；另设一条同步校验线，只自动修正能客观核对的错误。编辑在方向和大纲两处可选介入，不介入时按默认规则继续。

# 一、问题定义

| 项目 | 定义 |
|---|---|
| 输入 | 一篇约 1 万字、已写完结局的短篇；编辑批量上传，后台自动生成 |
| 处理 | 保留切点之前的原文，删除切点之后的部分，从切点续写约 2 万字 |
| 输出 | 约 3 万字成品，交编辑审阅、修改、发布 |
| 性质 | 续写，不是扩写。切点之前的原文是既成事实，不改 |

为什么要删掉原文结尾：原文自带结局。从结局之后硬续，只能拖沓、重复同一种情绪。删掉的部分是用来把已经关上的门重新打开。

核心矛盾：切得早，续写空间大，但删掉的原作高光多，每个都要补回来；切得晚，原作高光都保住，但门快关上了，新冲突只能硬造。"从哪里续"和"续写后会不会更爽"是同一个问题。

# 二、产品原则

所有流程改动都要能回到这几条。

| # | 原则 |
|---|---|
| 1 | 续写，不是扩写。切点之前的原文不改 |
| 2 | 类型不能变。"爽"按书定义（打脸、追悔、甜宠……），由类型契约约束 |
| 3 | 切点必须落在"门关上"（故事宣告尘埃落定）之前。切点属于每个方向，不是整本书一个 |
| 4 | 不丢：被删的原作高光（爽点、情感、反转）只能保留或加码，可以挪位置 |
| 5 | 新高：续写的终局高光至少与原作最强高光持平，目标是超过 |
| 6 | 2 万字靠第二个冲突撑起来，冲突必须来自原作的剩余势能 |
| 7 | 形式贴近原作：章长、对话占比、章尾落在事件上，用代码对照原文量化 |
| 8 | 若非必要，勿增实体。给写作喂的故事档案、多方向打分先不做 |
| 9 | 写作与校验分线。质量判断永不触发自动改写，只有可客观核对的错误可以自动处理，且只改局部 |
| 10 | 方向、大纲两处编辑可选介入，不介入时按默认规则继续，编辑改动记为反馈信号 |
| 11 | 编辑定义目标，机评放大目标。质量结论以编辑评价为准，上线后以读者数据为准 |

# 三、整体流程

| 步骤 | 节点 | 做什么 | 编辑 | 调用 |
|---|---|---|---|---|
| 1 | 批量上传 | 编辑上传多本原文 | 必须 | — |
| 2 | N1 原文理解 | 产出类型契约、高光清单、门关上位置、剩余势能、人物 | 只看不改 | 1 次 |
| 3 | N2 方向生成 | 三条路线，每条自带切点、高光账本、第二冲突 | 可选：选择或否决 | 1 次 |
| 4 | 默认选择 | 编辑不介入时自动选稳妥路线 | — | 0 |
| 5 | N4 大纲 | 2 万字的宏观结构与逐章细纲 | 可选：确认或修改 | 1 次 |
| 6 | N6 写作线 | 逐章写作，全文注入 | — | 每章 1 次 |
| 7 | 校验线 | 每章抽取事实、同步比对、分级处理 | — | 每章 1 次 |
| 8 | N7 全文建议 | 质量层面的批注，不改正文 | — | 1 次 |
| 9 | 编辑审阅 | 阅读、修改、给可发档位 | 必须 | — |

批量模式下，所有书先跑到方向，编辑集中选一遍；再跑到大纲，编辑集中看一遍；然后自动写完。编辑在两个时间点各批量处理一次，不需要逐本跟进。

# 四、各节点设计

## 4.1 N1 原文理解

模型直接产出，编辑只看不改。这一步决定后面所有节点的方向，上一轮类型跑偏就是从这里开始的。

| 输出 | 内容 | 用途 |
|---|---|---|
| 类型契约 | 具体类型、读者要的爽感、读者期待、反派应有下场、禁止的走向 | 约束方向和写作，防止类型跑偏 |
| 高光清单 | 每个高光的章号、类型（爽点/情感/反转）、强度 1～5 | 计算切点删掉了什么 |
| 低谷清单 | 主角受压的位置和持续章数 | 限制续写中主角受压的长度 |
| 门关上位置 | 故事宣告尘埃落定的章号 | 切点上限 |
| 剩余势能 | 漏网反派、未兑现狠话、未用完的设定或谜团、未展开人物、主角软肋；每条附原文依据和强度 | 第二冲突的唯一来源 |
| 人物 | 行为特征（附原文依据）、原作结局时的处境 | 防止人设崩 |

强度有统一标尺：5 为改变主角命运或核心真相揭晓，3 为一次完整的当众打脸，1 为铺垫性小爽点。

## 4.2 N2 方向生成

三个方向固定走三条路线，差异在切点、势能和高光处理方式，而不是换三个套路。

| 路线 | 做法 | 不成立时 |
|---|---|---|
| 稳妥 | 切得较晚，保留原作高潮；用最强的一条势能造出第二冲突 | — |
| 深挖 | 切在原作高潮之前，把高潮拆成几级逐步兑现，最终清算放到最后 | 保留比例低于 60% 时不生成 |
| 换路 | 与稳妥同一切点，第二冲突换另一条势能 | 没有其他强度 ≥ 3 的势能时不生成 |

每个方向必须给出：切点和保留比例、高光账本（每个被删高光的去处和处理方式，加码要写明维度）、需要从被删章节带过去的事实、第二冲突及所用势能、新增人物（只能来自某条势能）、主干升级节点、反派下场、终局高光、续写开头。

代码可检查项：切点 ≤ 门关上、保留比例 ≥ 60%（代码计算，不信模型填的值）、账本覆盖全部被删高光、势能可在清单中找到且强度 ≥ 3。

## 4.3 编辑介入与默认规则

| 设计 | 内容 |
|---|---|
| 介入方式 | 方向和大纲两处可以介入也可以不介入 |
| 默认规则 | 方向默认选稳妥路线：保留原作高潮，降级风险最小 |
| 为什么不用模型打分 | 模型品味未经验证，容易偏回它自己的默认叙事 |
| 交互 | 系统先按默认规则选好，编辑看到"已选稳妥路线"，不对再改 |
| 反馈信号 | 编辑改选是强信号，跳过视为默认接受（弱信号）；否决时从固定理由中选一个 |
| 规则演进 | 如果某题材编辑总是改选同一路线，默认规则改为按题材区分 |
| 评测集 | 评测集上必选，保证校准数据完整；生产环境可选 |

## 4.4 N4 大纲

**这是目前最没有设计的核心决策。** 编辑评分最低的一项是叙事节奏，而节奏主要由这一步决定。

| 已定 | 内容 |
|---|---|
| 章长 | 按原文章长中位数（约 1000 字），2 万字约 20 章，不再写死 2500 字 |
| 高光 | 必须覆盖账本里的全部被删高光 |
| 爽点密度 | 在本节点控制，N2 只给主干升级节点 |

| 待定 | 内容 |
|---|---|
| 宏观结构 | 2 万字中间放几个小高潮；第二冲突最晚在第几章亮出来；付费卡点在哪 |
| 节拍模板 | 是否用套路卡作为节拍模板。网文节奏高度模式化，适合用规则定 |
| 节奏规则来源 | 先请编辑在几本原作上标注爽点位置，归纳出节奏，再定规则 |

## 4.5 N6 写作线

| 设计 | 内容 |
|---|---|
| 输入 | 切点前原文 + 方向带过来的事实 + 全部已写前章 + 本章细纲 |
| 不阻断 | 写作不等待质量审核，不因质量判断重写 |
| 章尾 | 落在事件或对话上，不落在内心感悟 |
| AI 句式 | 编辑点名的句式写进反例 |
| 语气锚点 | 从原文中摘出最有态度的段落（打脸、狠话、反派嘴脸）作为示例，对抗模型把爽文写成成长文的默认倾向 |

为什么全文注入还会出错：模型并不缺信息，而是写某一章时没有注意到几万字里的那一句。所以一致性不靠给写作喂更多信息解决，而靠独立的校验线。

## 4.6 校验线

| 设计 | 内容 |
|---|---|
| 做法 | 每写完一章，用一次小调用只读这一章，抽取它确立的事实，追加进事实日志 |
| 日志初始化 | 由切点前的原文抽取 |
| 条目类型 | 物品状态、谁在什么时候知道了什么、人物关系、时间、金额与称谓 |
| 重点 | "谁知道了什么"的信息差优先做细。打脸类爽点建立在信息不对称上，信息差错位，爽点就塌了 |
| 比对方式 | 只比同一对象的条目，不拿新章比全文；每条冲突附两边章号和原句 |
| 与旧故事档案的区别 | 旧档案喂给写作，压缩写作的上下文；事实日志只给校验用，写作不受影响 |
| 同步 | 第 N 章校验完再写第 N+1 章。批量模式下并行发生在书与书之间，串行校验几乎不影响吞吐；同步可以避免错误传染给后续章节 |

分级处理：

| 级别 | 问题类型 | 处理 |
|---|---|---|
| 1 | 代码硬指标：章长、禁用句式 | 自动处理。章长超过原文 1.5 倍时优先在自然断点拆章，不让模型压缩 |
| 2 | 与切点前原文冲突的事实，且该类已验证精确率高 | 自动局部修改，只改出错的句子，最多 1 次；改不好转成批注 |
| 3 | 两段续写之间的冲突，或精确率未验证的类别 | 只批注，交给编辑判断 |
| 4 | 质量判断：节奏、爽感、AI 语感 | 永不自动改，由 N7 给建议或交给编辑 |

上线方式：一开始所有类别都按第 3 级只批注；用埋错测试测出每类的精确率，达到阈值（暂定 90%）的类别再升为第 2 级。

历史教训：此前一版用质量判断触发整章自动重写，重写次数多、不收敛，几乎没有一章通过。标准模糊的判断不能触发自动改写；整章重写会引入新错误和文风漂移。

## 4.7 N7 全文建议

只给质量层面的批注（节奏、爽感、人物），不拦截、不改正文。它的价值尚未验证：编辑会不会看批注、批注准不准都还不知道。

## 4.8 编辑改稿：目前的空白

核心命题是改稿成本，但现有流程里编辑只能阅读和打分。面对一份六成能用的 2 万字稿，编辑真正需要的是：选中某几章，用一句话说明问题（例如"节奏拖了，让反派提前出手"），然后局部重新生成。

| 待定 | 说明 |
|---|---|
| 编辑的角色 | 审稿人（接受或拒绝）还是导演（指挥模型局部重写） |
| 局部重生成 | 重写某几章后，校验线如何更新、后续章节是否需要跟着改 |

这一环可能是降低改稿成本杠杆最大的地方，需要单独设计。

# 五、数据流

| 数据 | 产生于 | 流向 | 说明 |
|---|---|---|---|
| 原文理解 | N1 | N2、N4、N6 | 类型契约贯穿全流程 |
| 切点 | 选定的方向 | N4、N6、N7、校验线 | 决定后续节点能看到的原文范围 |
| 带过去的事实 | 选定的方向 | N4、N6 | 被删章节里续写要用的事实，在续写前段重新交代 |
| 事实日志 | 校验线 | 只给校验线 | 不作为写作输入 |
| 冲突批注 | 校验线 | 编辑 | 附两边原句，便于判断真假 |
| 编辑操作 | 选路线、改大纲、改正文、可发档位 | 评测与策略迭代 | 投产后是零成本的真实标签 |

# 六、交给模型能力、不做工程机制的部分

| 部分 | 处理方式 |
|---|---|
| 文笔、AI 语感 | 换模型、给原文示例和反例 |
| 单章内部的场景写法 | 交给写作模型 |
| 细节层面的连贯 | 由校验线兜底，不给写作加机制 |

这些在评测中作为"写作模型"一个变量，用方案 × 模型的对照实验来判断瓶颈在哪一层。

# 七、暂时不做

| 不做 | 原因 |
|---|---|
| 给写作喂故事档案 | 压缩写作上下文，且未证明必要 |
| 多方向模型打分 | 模型品味未经验证 |
| 质量判断触发的自动重写 | 已证明不收敛 |
| 引文超长作废整本批注、改一章重审全文、原文长度上限 | 等编辑真正用起来遇到时再修 |

| 1 | 把提示词草案（N1、N2）接入流程，章长改为按原文中位数 | 新版方向与大纲 |

| 3 | 实现校验线，全部类别先只批注 | 事实日志与冲突批注 |

| 5 | 设计编辑改稿环节 | 局部重生成方案 |

# 九、待决问题

| 问题 | 为什么重要 | 谁来定 |
|---|---|---|
| 新高是"持平即达标"还是"必须超过" | 决定方向生成的门槛 | 产品，参考编辑反馈 |
| 保留原文比例下限 | 决定深挖路线何时不成立 | 产品，用编辑选择校准 |
| 付费卡点位置 | 决定高潮和第二冲突的位置 | 产品或平台 |
| 续写给新读者还是老读者看 | 老读者已看过前文，续写开头必须立刻抓人 | 产品 |
| 校验线自动修改的精确率阈值 | 决定哪些类别可以自动修改 | 用埋错测试数据定 |
| 拆章后章数与大纲不对应 | 影响大纲与成稿的对应关系 | 实现时定 |
| 编辑改稿时的角色 | 决定改稿环节怎么设计 | 产品，结合编辑访谈 |
