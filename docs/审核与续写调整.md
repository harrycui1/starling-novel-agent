## 落地内容

| 修改 | 现在的行为 |
|---|---|
| 重写门禁 | 只有模型显式block才拦截；高严重度且可修复的一致性问题进入重写 |
| 审核引文 | 失配条目丢弃并提示，保留其他审核意见，不因单条失配让整本失败 |
| 人名与字数 | 跳过已登记名字/别名的片段；未知人名、篇幅偏差只作为编辑提示，重复人名提示去重 |
| 道具和场景 | 档案新增关键道具持有人、位置、状态和场景状态；逐章补丁更新，代码限制未知持有人/在场人物 |
| 梗概与衔接 | 原文logline顶部只显示一次；方向synopsis只写续写，另有opening_moment指向原文结尾 |
| 原文理解 | 正常一次读完，仍逐章输出摘要并抽取伏笔、证据和状态；文风统计与证据核对由代码完成 |
| 批量评审 | 候选顺序随机打乱后一次比较，按候选ID校验完整性；每个维度理由和展示位置保留 |
| 场景字数 | 每场景有字数预算，代码检查合计；旧细纲缺失预算时按剩余篇幅补齐 |
| 细纲重试 | 章号、角色、伏笔覆盖和字数检查纳入结构化重试，把具体错误反馈给模型 |
| 分节提示词 | 人物、前情、道具、场景等分节排列，上一章与本章细纲放在材料末尾 |
| 去翻译腔 | 写作/重写提示词加入自然中文约束及对照例子，扩充高频套话词表 |
| 评分展示 | 剧情梗概和评分分开，AI分数与理由默认折叠 |
| 手动方向 | 提供主套路词表，规范化后可编辑再确认；操作前后入日志 |
| 精简审核 | 只保留相关人物/规则、道具与场景状态、上一章末尾800字、本章细纲和正文；不带风格样例和全书摘要 |

所有修改过的提示词版本更新为 `2026-10-27.2`。

## 旧任务兼容

新增字段位于已有JSON产物中，读取提供默认值，无数据库列变更。旧档案第一次继续写作时，从原文补齐道具与场景状态，并重建缺少新状态字段的旧缓存。

旧章稿和审核历史不删除。旧规则合并出的block会重新分类；旧提示词下模型自己给出的block要用新提示词重新审核。章节checkpoint也检查新策略，避免旧block稿被直接跳过。重写次数仍有上限。

旧方向卡保留历史内容，不静默改写。换一批方向才能获得新格式；旧卡也可在修改时补上衔接瞬间。

## 验证和解释边界

- 先写回归复现“high变block、引文导致失败”，再修复；精简验证覆盖重写实际触发、显式block、逐条引文过滤、旧模型block重新审核、名字片段、道具/场景补丁、场景预算、精简材料、单次理解/批量评分、细纲重试与手动方向编辑。
- 原有端到端冒烟继续覆盖断点恢复、人工确认、改稿、提交和TXT/Word导出。
- TypeScript与生产构建、Python静态错误检查通过；Alembic检查无新列迁移。
- 从旧真实数据库拷贝的任务，用固定LLM单独验证可以恢复到awaiting_review并保留历史；这是控制流验证，不是质量评测。
- 实际模型的阶段重放已观察到新稿被判revise后生成rev1，旧版相同父方向/大纲/细纲没有触发自动重写。
- 同一旧失败章的材料重组：旧完整上下文17,798字符，新审核材料4,522字符，上一章只取800字符；该数字不等于实际token或完整成本。

完整结果在真实运行结束后补记。phase1（重写规则+精简审核）是局部阶段实验，部分样本为partial，不能把它当成整本完成率。final为合并改动，只说明总体效果，不能将全部差异归因到某一个单项改动。不同模型抽样也有波动。首稿通过率同时受到门禁定义变化影响，不能直接当作文学质量提升；质量仍需独立审核与编辑抽查。
