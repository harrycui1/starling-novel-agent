# 全文精简流程

日期：2026-10-27。目标：编辑输入约一万字开头，经方向和大纲确认后拿到约两万字续写，问题由编辑判断和修正。

## 流程与调用

| 阶段 | 输入与产出 | 正常调用次数 |
|---|---|---:|
| N1 理解 | 全部原文 → 梗概、人物表、原文结束处境；存 SourceUnderstanding | 1 |
| N2 方向 | 全部原文 → 三个续写方向，明确承接点；代码只校验数量与主套路不重复 | 1 |
| 编辑选方向 | 选择、修改、换批或手动输入；完整记操作日志 | 0 |
| N4 合并大纲 | 原文＋选定方向 → 整体走向、每章事件、爽点、停止点、目标字数 | 1 |
| 编辑确认大纲 | 修改并确认后才能写作；章节连续且字数合计匹配目标 | 0 |
| N6 写作 | 全部原文＋当前版本全部已写前章＋确认大纲＋本章要求＋写作规范 | 默认8 |
| N7 审核 | 全部原文＋全部续写＋确认大纲 → 按章批注 | 1 |
| 编辑审阅并提交 | 修改、带意见重写、重新审核或直接提交；审核意见不设门禁 | 0 |

默认12次；人工请求和模型服务/JSON结构重试额外计数。先完成写作再统一审核，避免审核异常卡住后续章。手动方向需要一次整理，再由编辑确认。没有自动选方向或默认打分排名。

## 持久化与恢复

- 原文、方向批次、方向选择与改动、大纲修订、章稿修订、编辑行为、模型调用、进度事件均保留。
- N1 已存理解结果时不重新理解。N6 以当前章稿为断点，恢复时复用已写章节，不因审核意见重写。
- N7 批注记录当前全文的章稿ID与重审请求号，用于判断本次审核是否已经存好。这只是批注归属，不再维护故事状态或按章重建档案。
- 编辑改稿后按当前修订全文重审。后续章保留衔接提醒，但不阻止提交。重写中断恢复时，已保存的新稿不会再次自动改写。
- 审核服务/结构失败存入每章 `llm_review.error`，状态仍到 `awaiting_review`；批注显示不可用。人工点击重新审核全文可重试。
- 模型审核不做逐字引文校验，不因引文失配卡住任务。批注的准确性由编辑结合正文判断。

## 兼容与移除

新增迁移 `0002`，仅增加 SourceUnderstanding 表。保留旧数据库中的故事档案、细纲表和其他历史数据，不修改初始迁移；旧项目可以读历史数据。旧大纲缺少目标字数时，写作按版本目标均分；旧 N5 断点直接进入写作。

已关闭并移除执行代码：逐章档案更新和快照核对、引用核对、八选三评分与平台套路扣分、细纲单独调用、自动重写、人名分词、上下文裁剪。字数、禁用结尾和高频表达保留为编辑提示。写作提示词明确区分已发生正文与未来大纲，约束人物、道具、视角及自然中文表达。

旧表结构留下以便查历史，不预留新的长篇或短剧扩展机制。未来原文超出模型容量时，应作为新的需求处理。

## 验证

- 基准分支原有冒烟通过。精简版3条综合集成测试通过，覆盖默认8章12次、超过旧60k预算的原文全文输入、所有前章逐字传入、审核block/失配引文/服务失败不阻断、断点复用、改稿与重写上下文、方向日志、TXT/Word导出。
- 已在独立新建环境安装依赖，后端测试通过；前端TypeScript和生产构建通过。
- Demo评测驱动实录12次调用、8章、8条审核。演示数据不作为文学质量评估。
- 真实样本的结果摘要见 [精简流程实测](精简流程实测.md)，完整结果保存在本机 `data/comparison/`，输入、模型与提示词信息可追溯。文学质量和可用程度需要编辑盲评，不能从调用数下降推断。
